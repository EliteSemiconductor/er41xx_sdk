# ER4100_EzFirm_802154TxRx_PER

## Overview

This project demonstrates **Packet Error Rate (PER) measurement** in IEEE 802.15.4 mode with the ER4100 RF transceiver on an N76E003 (8051) MCU.

Pressing the button (P0.5) triggers a burst of **500 TX packets** at 50 ms intervals.
The ER4100 hardware CRC validates each received packet. The IRQ handler counts good packets (`IS_INT_ST_RX`) and CRC-error packets (`IS_INT_ST_RXERR`) separately.
A **running PER** is printed after every received packet, and a final PER summary is printed when 500 packets have been tallied.

**Difference vs 802154TxRx:**

| | 802154TxRx | 802154TxRx_PER |
|---|---|---|
| TX trigger | Single packet per P05 press | Burst of 500 packets per P05 press |
| TX interval | Immediate | 50 ms between packets |
| RX action | Print data + RSSI | Count ok/error via hardware CRC, print running PER |
| CRC check | Hardware (pass/fail event) | Hardware — IS_INT_ST_RX (ok) / IS_INT_ST_RXERR (error) |
| PER report | — | Running % per packet + final summary at 500 |

## 802.15.4 Packet Format

```
[PHR][MHR][PAYLOAD][CRC]
```

[Field Description]
  PHR      : 1 byte   Total packet length (MHR + PAYLOAD + CRC)
  MHR      : 15 bytes Hard-coded MAC Header (FrameCtrl, SeqNum, PAN ID, addresses)
  PAYLOAD  : variable  Sequence number + sequential fill bytes
  CRC      : 2 bytes   CRC-16, appended automatically by hardware

MHR template (`SamplePattern[]`):
```c
0x41,0xC8,0x00,       // [FrameCtrl:41C8][SeqNum:00]
0xCD,0xAB,0xFF,0xFF,  // [DestPAN_ID:ABCD][DestAddr:FFFF]
0x02,0x00,0x00,0xAB,  // [SrcAddr(LE): 0x000000AAAB000002]
0xAA,0x00,0x00,0x00,
```

> **Note:** In 802.15.4 RX mode, the length parameter of `TRx_RX_Trigger()` is ignored; the MAC layer reads the actual packet length from the PHR.

## RX Verification and PER Calculation

On each received packet the IRQ handler (`XTAPP_IrqHdlr`) checks the interrupt status:

- `IS_INT_ST_RX` (hardware CRC pass):
  - `gPerRxOk++`
  - Prints `RX OK #<seq>  rssi: -<val>`

- `IS_INT_ST_RXERR` (hardware CRC fail):
  - Prints `RX CRC ERR  rssi: -<val>` with `CrcErr` / `FmtErr` detail flags
  - Calls `TRx_RX_FIFOReset()` to recover RX FIFO

After either event:
- Prints running PER: `PER: <err>/<total> = <pct>%`
- When `(gPerRxOk + gPerRxErr) >= 500`: prints final summary and resets both counters

**PER formula:**

```
PER(%) = gPerRxErr * 100 / (gPerRxOk + gPerRxErr)
```

> **Note:** Completely lost packets produce no IRQ event and are not counted.
> The final total may be less than 500 if packets are lost before reaching the receiver.

## Extended Notes

### Common.h as the Single Include Entry
All `.c` files only need `#include "Common.h"` to get all typedefs, MCU headers, and module declarations.

### SPI Implementation
Uses **Software SPI (GPIO bit-bang)**. Pin definitions are centralized in `RF_Hal.h`:

[SPI Pin Assignment]
  NIRQ  P03  Interrupt input
  MOSI  P00  SPI data output
  MISO  P01  SPI data input
  SCK   P10  SPI clock
  NSS   P15  SPI chip select

### Hardware CRC
The ER4100 appends and verifies CRC-16 automatically.
On RX, the result is reflected in the interrupt status:
- `IS_INT_ST_RX`    — CRC passed; FIFO contains valid payload
- `IS_INT_ST_RXERR` — CRC failed; call `TRx_RX_FIFOReset()` before re-arming RX

### PER Counter Variables

- `gPerRxOk`  : packets received with hardware CRC pass
- `gPerRxErr` : packets received with hardware CRC fail
- Both are reset to 0 after the final PER summary is printed

### Startup UART Log

On power-up, `main.c` outputs the project name and init result via UART:

  "802154TxRx_PER : init done\r\n"  — initialization successful
  "802154TxRx_PER : init fail\r\n"  — initialization failed

### XTAPP_Scan() Error Guard

`XTAPP_Scan()` returns immediately if `rf_err_mode == 1` (init failed), preventing RF access when the transceiver is not initialized.
