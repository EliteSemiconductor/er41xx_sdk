ER4100 SDK_EZ  —  Revision Notes
Date    : 2026-04-12
Previous: ER4100 Lierda delivery  2026-02-06

================================================================================
OVERVIEW
================================================================================
The 2026-02-06 delivery was a minimal package tailored specifically for the
Lierda application: three custom EzFirm projects + one customer firmware (CA51_)
+ EzGen V1.0.

The current SDK_EZ is a fully restructured, general-purpose SDK.  It replaces
the Lierda-specific package entirely and covers a much wider set of use cases.
Project naming, file structure, and documentation have all been standardised.

================================================================================
1.  EzGen  (PC configuration tool)
================================================================================
  Previous   EzGen V1.0
  Current    EzGen V2.1

  Changes in V2.1:
  - GPIO section
      Configure each GPIO pin function (e.g. TR_BSY output on GPIO1).
      TR_BSY is high while the RX window is open — useful for oscilloscope
      measurement of WOR RX window timing.
  - TRANSPARENT WITH PRESYNC mode
      New RF mode option in the configuration GUI.
  - Frequency Table
      Multi-frequency channel table can be defined directly in the GUI.
  - Batch .ini file loading
      Multiple EzGen .ini files can be loaded and processed in one operation.

--------------------------------------------------------------------------------
Update 2026-08-10: EzGen V2.1 -> EzCodeGen V2.2
--------------------------------------------------------------------------------
  The tool is renamed EzGen -> EzCodeGen (build 20260805).
  Changes in the generated SPI_ER41xx_config.h:
  - _D_CODE compatibility macro is now embedded directly in the generated
    header (covers SDCC / Keil C51 / IAR / AVR / XC8 / Renesas CC-RL /
    CA78K0R / ARM, etc.), matching the macro previously supplied via the
    shared compiler_compat.h.  channel_pll_table, Initial_Reg_Array,
    TRx_Config_Array and TRx_ConfigEx_Array are now declared with
    "_D_CODE const" instead of the old hard-coded "code const"
    (Keil C51 only) qualifier.
  - TRx_Config_Array[] reordered and extended: a new PA (Power Amplifier)
    setting block (registers 0x1f00~0x1f38, 15 entries) is generated ahead
    of the TX/RX sections.  New order: PA setting -> TX setting ->
    RX setting -> Freq/Deviation/DataRate -> Freq (Xtal) -> Power config.
  All 18 EzFirm projects in this repository have been updated to match
  (compiler_compat.h added per project, all four arrays switched to
  "_D_CODE const").

2.  EzFirm  (embedded firmware examples)
================================================================================

--- 2a.  Project naming ---

  Previous (Lierda-specific)          Current (standard EzFirm)
  ----------------------------------  ----------------------------------
  ER4100_Lierda_TransparentTxRx       ER4100_EzFirm_TransTxRx
  ER4100_Lierda_TransparentLongPkt    ER4100_EzFirm_TransTxRx_LongPkt
  ER4100_Lierda_TransparentWOR        ER4100_EzFirm_TransWOR
  (none)                              ER4100_EzFirm_TransWOR_Ack  (new)
  CA51_ customer firmware             not included in SDK_EZ

--- 2b.  Long packet (TransparentLongPkt → TransTxRx_LongPkt) ---

  Both versions support payloads up to ~512 bytes using FIFO threshold
  management.  The new version uses standardised API names and the
  SPI_ER41xx_config.h is generated by EzGen V2.1.

--- 2c.  WOR (TransparentWOR → TransWOR / TransWOR_Ack) ---

  Previous: single RX-only WOR project.
            Preamble detection uses 0xAAAAAAAA; after wake-up the chip
            switches syncword to 0x89CB8DC3 to receive the actual packet.

  Current:  two WOR projects.
    TransWOR     — receive-only, same basic flow as previous.
    TransWOR_Ack — after receiving a packet, automatically sends a 3-byte
                   "ACK" reply (200 ms delay, then TX, then restart WOR).

  WOR parameters (both current projects):
    WUT period   : 100 ms  (configurable: 10 / 50 / 100 / 500 ms, 1 / 2 / 4 s)
    RX window    : 80 ms   (WOR_CNT=4 × 20 ms)
    Syncword     : configured via EzGen V2.1 / SPI_ER41xx_config.h
    GPIO1        : pre-configured as TR_BSY output for RX window measurement

--- 2d.  New projects not in previous delivery ---

  Transparent mode:
    ER4100_EzFirm_TransWOR_Ack         WOR RX with automatic ACK reply
    ER4100_EzFirm_TransTxRx_PER        Packet Error Rate test (transparent)

  IEEE 802.15.4 mode:
    ER4100_EzFirm_802154TxRx           Basic 802.15.4 TX/RX with HW CRC
    ER4100_EzFirm_802154TxRx_Addressing  Address / PANID filtering demo
    ER4100_EzFirm_802154TxRx_CCA       TX with Clear Channel Assessment
    ER4100_EzFirm_802154TxRx_PER       Packet Error Rate test (802.15.4)

  NFC mode  (all new):
    ER4100_EzFirm_NFC_Field_Interrupt  Field detection via INT_N interrupt
    ER4100_EzFirm_NFC_Field_Polling    Field detection via SPI PWRGOOD polling
    ER4100_EzFirm_NFC_Menu             Interactive UART menu: read/write blocks
    ER4100_EzFirm_NFC_ReadWrite        MCU reads/writes NFC memory (Block 4~19)
    ER4100_EzFirm_NFC_StatusTrigger    Field attach via INT_N; status event via
                                       USER_CFG4; detach via SPI polling

  Test / Tool:
    ER4100_EzFirm_SingleTone           Continuous carrier for RF test
    ER4100_EzFirm_RSSI_Scan            Channel RSSI scan using CCA mode
    ER4100_EzFirm_PowerSaving          Deep sleep / wake triggered by P05
    ER4100_EzFirm_PowerSaving_WUT      Deep sleep with auto wake via WUT timer

================================================================================
3.  RF driver layer  (SPI_ER41xx)
================================================================================
  - API names standardised: TRX_WRITEREG_U32, SET_U8_ARRAY
    (old names TRX_WRITEREG_uint32_t, SET_uint8_t_ARRAY removed)
  - Feature flags per project:
      EXTERN_RF_APIS_CCA         — projects using CCA
      EXTERN_RF_APIS_WUT         — projects using WOR / WUT
      EXTERN_RF_APIS_SINGLE_TONE — SingleTone project only
  - NFC projects use RF_NFC_APP.c / RF_NFC_APP.h
    (other projects use RF_App.c / RF_App.h)

================================================================================
4.  Documentation
================================================================================
  - Every project now ships two Markdown documents:
      <ProjectName>_Eng.md        English
      <ProjectName>_SChinese.md   Simplified Chinese
  - Documents cover: overview, flow diagram, parameters, API reference,
    directory structure, layer architecture, SPI/UART pin assignment,
    Keil include paths, startup UART log, XTAPP_Scan error guard.
  - README.md and README_SC.md list all 18 projects with descriptions.
  - UART pin assignment documented: TXD = P06, RXD = P07, 115200 baud.
